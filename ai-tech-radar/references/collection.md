# 从主题到真实材料

## 限定本轮范围

沿用目标主题、公司／Lab、时间窗口、工程／研究问题和交付要求。只有缺失信息会改变正确性或成本时补问。无明确数量的探索先精选少量高相关原始材料；不把“追踪”自动理解成无限采集或建立后台任务。

来源清单包含公司、团队、可信入口、目标主题、上轮检查时间和访问状态。团队可以有官网、公众号、论文页、作者页、GitHub 等多个入口，不用媒体类型拆成多套库。公司和团队区分；不确定具体 Lab 就记录未知。关注论文时保留作者在发表时的归属，不能把当前任职反填历史记录。

沿用用户 watchlist；首次建立或扩充时从[固定来源清单](source-list.md)选择相关入口，按[清单维护](tracking.md#来源清单与扩充)新增来源。目录、单篇工作锚点、发现聚合器用途分开，单篇文章不能充当团队完整更新列表。官方公众号受限时，可把已核实的官方技术博客作为独立来源，同时保留微信入口的访问边界。

## 获取顺序

1. 用现有搜索工具找到候选，通过官方站点、作者页或论文确认出处。可组合 `site:团队官网 agent evaluation`、`团队名 智能体 评测 技术`、`论文标题 code`。记录实际搜索范围和未覆盖项。
2. 有公开 RSS／Atom 时按其条目发现更新；没有则检查官方目录或搜索。读详情正文才能做内容分析，不能只凭搜索摘要、标签或标题写结论。发布日、论文版本日和采集日分开保存。
3. 公众号按下节发现候选、读取原文。直接 HTTP／Jina 受限时，检查已有浏览器读取能力；仍无法取得正文，再找官方同源博客或作者确认的公开全文。分别记录实际路径与结果，镜像不计为微信采集成功，转载亦不自动提升为原始来源。
4. 论文同时从 arXiv、Hugging Face Papers、OpenReview／作者公开版本发现，不要求先有公司博客。团队署名、模板品牌标识与官方互链按[研究归属规则](research.md#从论文平台补齐团队研究)收录。摘要足以筛选，方法和实验结论必须读到对应章节；HF `.md` 也可能只有摘要，下载成功不代表全文精读。无公开代码时保留这一事实，不猜仓库地址。
5. 代码使用官方仓库 README 与实际模块，记录 `repo/ref/path` 和检查日期。核实任务、数据许可、环境与资源要求后，再写实践建议；默认不运行模型。

使用目标环境已有的搜索、网页／浏览器和 GitHub 能力。读取失败保留原始错误，可按现有工具说明选择有限替代路径；不得隐藏缺失、绕过验证码或自动登录。

核实公众号时同时检查账号身份和运营归属。官方云社区的普通用户或员工转载，不足以证明其所提公众号由公司官方运营；需明确的官方账号说明、认证主体或公司官方互链。没有可读历史目录时，沿已核实官方镜像目录或搜索发现新文章，再核对账号身份；不能只重复访问作为示例的旧文章就宣称已追踪账号更新。

## 公众号发现与正文读取

任务包含文章发现／采集时使用此路径；只扩充来源时仍只核实入口和身份，不默认下载文章。

- 已知公众号名，用[搜狗微信](https://weixin.sogou.com/)的公众号入口核对账号，文章入口组合“账号名＋主题”发现候选；已知题名或内容片段时用题名／关键词定位。账号搜索未命中不证明账号不存在；文章关键词命中也不证明由该账号发布。
- 已有可信微信原链时可直接读取，不要求先重复搜索。搜狗结果常是中间跳转链接，沿实际返回链接取得最终微信地址，再核对发布者；第三方索引、转载和解读单列为发现线索。

### 名称核对与检索补救

以用户指定的公司或团队为范围时，检查其相关团队入口，不将公司固定为一个公众号。不同团队账号各留来源 ID；没有确认公众号的公司可沿官网、博客、论文或代码入口继续。账号显示名、历史名称与搜索索引名分别记录：只有相同 `biz`、明确更名声明或官方互链等证据才能建立同号关系，名称相似不够；同号关系也不证明运营主体始终相同。未核关系保留候选，不加入已确认别名。

账号名加主题未找到合适原文时，按缺口选择补救路径，无需每次执行全部步骤：

- 从公司官方技术目录、团队介绍或年度目录提取具体题名、业务场景和项目词，再用完整题名、辨识度高的片段或“团队／账号名＋场景词”搜索；搜索索引旧名称可作为查询线索。
- 搜狗结果不足时，用通用网页搜索补题名和原链。检查官方页面及转载页的实际微信出链，跟随到原文后核对发布账号；没有出链的转载只能提供搜索线索，不据此补造微信地址。
- 官方链接受阻时，区分目标页面不可读与搜索未命中；可沿题名继续定位同一工作，或选择范围内另一篇相关原始材料。不同文章独立记录，不能把目录中的效果数据移入另一篇正文。
- 有针对性的路径仍无原文时，保留“未找到／当前不可读／身份待核”的具体状态；有已核实的官方原始博客时可用于分析，并与微信正文成功分开计数。达到本轮范围或预算后停止扩搜，不以单次空结果推断账号不存在。

保存查询、实际逐跳链接、发布者与标识、证据日期及未闭合关系；分别说明搜索定位、官方关联核验、原文阅读各自取得了什么证据。已核账号的临时签名链接只作当次访问记录，固定来源优先保存稳定身份入口、实际取得的稳定原链或明确标注的搜索入口。

### 搜索与读取工具

- 环境已有 OpenCLI 时，先看 `opencli weixin search --help`、`opencli weixin download --help` 与 `opencli doctor`，确认命令和浏览器连接。它通过 Chrome／Browser Bridge 搜索和读正文，不需要公众号发布后台。其他已安装的公众号读取 skill／工具可按各自文档等效使用；不为一次读取自动安装或登录。

```bash
# 发现文章；数量与页码按本轮范围选择
opencli weixin search '公众号名 主题或题名' -f json

# 已取得微信文章原链；输出放本轮工作区
opencli weixin download --url 'https://mp.weixin.qq.com/s/ARTICLE_ID' \
  --output 'tmp/<run-id>/wechat' --download-images false -f json
```

`search` 返回标题、摘要、时间和搜狗链接，未必包含发布账号，也不读取全文。如果适配器返回导航错误而没有明确策略拒绝，可在本轮独立浏览器会话打开同一搜狗查询页（`https://weixin.sogou.com/weixin?type=2&query=<编码后的查询>`），用 `state` 核实是否显示正常结果；实际可读时保存页面查询、结果顺位及链接，分别记录“适配器失败”和“浏览器搜索页读取成功”。遇验证页或明确策略拒绝则停止该路径，不把失败改成成功。

需要跳转时使用已有浏览器打开实际返回链接，保存最终 URL；不要把搜狗链接直接交给只接受微信地址的下载命令。第三方文章若有真实“原文”链接，可继续跟随并核实最终公众号；只有题名提及而无链接时，不凭记忆或猜测补接来源链。`download` 的 `author` 通常是公众号显示名，正文个人署名另记。图片含关键方法或指标时按需核读；文字导出不代表已读图。

### 复用已加载会话导出

沿搜狗结果定位原文时，为本轮使用独立的 `opencli browser <session>` 会话，串行完成跳转和导出。原文已在该会话正常显示时，可直接运行本 skill 的 [wechat-export.mjs](../scripts/wechat-export.mjs)，不必再新开一次下载会话；尤其适合普通 `weixin download` 新会话遇验证、而原会话正文仍可读的情况。

```bash
# <session> 使用本轮独立名称；URL 必须来自实际搜索结果或页面链接
opencli browser '<session>' open '<搜狗结果或其中真实原文链接>'
opencli browser '<session>' eval '({url:location.href,title:document.title,publisher:document.querySelector("#js_name")?.innerText,chars:document.querySelector("#js_content")?.innerText.length,links:Array.from(document.querySelectorAll("#js_content a[href]")).map(a=>({text:a.innerText,url:a.href}))})'

# <skill-dir> 为当前实际技能目录；每篇使用独立输出目录和收据路径
node '<skill-dir>/scripts/wechat-export.mjs' \
  --session '<session>' --url '<本轮核实的微信文章地址>' \
  --publisher '<页面公众号显示名>' \
  --output 'tmp/<run-id>/article-01' --receipt 'tmp/<run-id>/article-01.receipt.json'

# 所需页面证据与导出均已保存后，只释放本轮自建会话
opencli browser '<session>' close
```

脚本需要现有 Node.js 与 OpenCLI，沿 PATH 中 `opencli` 的真实路径定位安装；非常规安装可用 `--opencli-root` 指向包根目录，先用 `--help` 查看。它复用原版 `Page` 与 `weixin/download`，保留导航和验证检测，不重写正文转换，也不安装或修改全局工具。此入口依赖 OpenCLI 内部模块布局；接口不兼容时明确失败，不自动改用未核实实现。

脚本核对目标文章、正文与可选公众号名：短链匹配路径，标准长链按 `__biz/mid/idx/sn` 匹配；搜狗返回的 `src=11` 签名地址则精确匹配其查询参数，仅忽略片段和 `poc_token`，不猜补文章标识。如果短链已重定向，传页面实际最终地址，并在路由记录保留前后关系。导出后回读身份与文件，保存前后元数据、原版结果行、实际文件大小和 SHA-256，遮盖自动附加的 `poc_token`。公众号显示名匹配不代替官网关联证据；正文首尾和分析所需章节仍需实际核读，图片未读须说明。

普通 `download` 即使退出 0，也可能返回 `failed`；同会话脚本仅在结果行与回读均成功时返回 0，其余非零并保留失败收据。不同调用的失败与成功分别记录。当前会话若是验证页、未加载正文或与目标不符，就停止该次导出，不处理验证码、不切换账号或禁用检测。`Navigation rejected` 不能直接当成目标站反爬；先保留错误及当次会话状态，不把已有页面的成功读取写成底层导航故障已修复。

材料记录注明 `collection_method=opencli_weixin_download_loaded_session`，`source_ref` 指向正式保存的正文，另引用收据和查询→结果→中间页（如有）→原文的逐跳关系。脚本不更新 watchlist、不启动岗位匹配；正式入库沿用下述目录记录流程。

成功后核对实际页面／导出正文的标题、账号、发布时间、正文首尾及所需章节，保存查询、跳转关系、读取方式、时间和证据。下载状态或文件大小不足以证明正文完整。直接请求失败与浏览器成功可同时保留；记录本次成功路径，不把旧失败改成成功。搜狗入口和目标微信文章都可能遇验证，失败时保留边界，不由一次失败推断永久不可读。

## 选择与关联

优先解释机制、业务约束、技术取舍、实验或失败的材料。发布新闻可发现技术报告，但不因大厂标题自动进入深度案例库。BlogrXiv 的精选收录可帮助发现来源，收录数量不能作为各 Lab 产量或活跃度的分母。

给独立工作分配稳定 `work_id`；同一工作的中英文博客、论文版本和代码都关联到它，材料各有 `material_id`。仅主题相似不能合并；论文 ID、官方互链或明确标题关系才支持同一工作判断。跨团队合作保留多方关系，不把共同工作重复当各自独立发现。

规范记录见[目录格式](tracking.md)。下述保存路径以[存储助手](../../ai-career/references/storage.md)选定的数据根目录为起点，传给工具时使用绝对路径。保留简短原文证据与定位，分析用自己的话总结。临时下载放 `tmp/<本轮>/`；正式材料引用的必要正文、源码和读取记录在生成 JSONL 前保存到 `data/evidence/<run-id>/` 或已有正式证据目录。已有不可变快照引用的临时路径继续保留，不为换目录改写历史时间或内容；备份包含这些被引用文件、JSONL、目录快照和 watchlist。公开技能包不分发采集全文或个人数据。
