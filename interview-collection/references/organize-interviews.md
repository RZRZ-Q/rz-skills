# 整理已有面经

从已有材料提取实际面试提问，保留原句和逐题出处。用户要求生成或更新岗位题库时进入[岗位题库](role-question-bank.md)；跨来源合并只发生在派生题库，原表保留原题。

## 读取与分篇

只读用户指定的文本、图片和已采集材料；给定链接尚无正文时按[采集子流程](find-interviews.md)读取，不补搜或跟随正文中的其他链接。没有可读正文就说明缺口，不从标题猜内容；搜索摘要、编号题单或 `body_truncated=false` 都不能单独证明实际面试。

- 只取主帖作者正文，排除评论、推荐和摘要；B站可用简介及已取得的字幕，字幕转录不等于视频画面已审看。未展开、未读图片或未读到末尾时说明实际覆盖；章节编号跳号本身不证明缺页。
- 一份可辨认经历为一篇，同一经历多轮合并；不同公司、岗位或独立招聘经历分别成篇。同公司同岗位不等于同一次投递，仅日期或轮次变化也不自动拆篇。原文分篇但关系未明时按篇保留并注明，不宣称已确认独立投递次数。
- 合集拆篇保留共同链接与原标题，用原篇章标题或“公司／岗位＋图号或段落”区分；跨图延续仍归同篇。普通面经缺少岗位或日期可记未知；无法分配到具体经历的摘录标记归属待确认，不拼成一场面试。
- 不同来源保持分开，同题不丢出处。截断、省略或重排后的问题不得继承缺口前的面经归属、日期或轮次，除非该片段自身有依据；局部缺失不否定此前归属清楚的完整条目。

## 提取面试信息

元数据必须属于本次经历；作者主帖标题可作依据，但文件名、招聘广告、他人经历和希望投递的岗位不能替代。合集共同信息仅在原文明示适用于各篇且无冲突时继承。

- **平台**：按规范来源链接识别牛客、小红书、知乎或“B站”；无链接时用材料明示值，否则填“无”。本地保存不抹去已知平台。
- **公司与岗位**：保留原称，按[公司与岗位归一](company-role.md)匹配标准值。仅有技术话题不确定岗位；调剂后以实际经历为准，不自动沿用投递通道。未知标准值不反向覆盖原称。
- **部门**：只填本场明示的部门、团队或业务线，否则填“无”；岗位或技术方向不是部门。
- **招聘类型**：“实习（日常）”“实习（暑期）”“实习（未注明）”“校招（秋招）”“校招（春招）”“校招（未注明）”“社招”“无”。只有大类则选“未注明”，全不明选“无”；泛化标签和日期不足以确定类型。岗位中的招聘阶段单独拆出，例如“大模型算法实习”对应岗位“大模型算法”和“实习（未注明）”，不改标题或题干。
- **轮次**：按原文明示的一面、二面、技术面、AI 面等顺序；未写才记未知，不用题目难度或顺序推断。项目／算法／八股等主题标题不是轮次，仅预约或待安排的轮次不计为已发生。
- **面试日期**：优先采用原文明示日期及可核实的跨年线索，保留精度 `YYYY-MM-DD`／`YYYY-MM`／`YYYY`；仍缺年时用已核实原帖发帖年补齐；无面试日期时可只填发帖年，不编造月日。使用发帖年时在补充说明标明“年份按发帖年补齐”或“仅有发帖年，面试日期未披露”，不作为[时间范围筛选](find-interviews.md#逐条判断)的独立证据。不用编辑、评论或采集时间补年；发帖年也未知时保留已有月日并注明“年份未知”，完全无日期则填“未知”。

## 保留实际提问与出处

实际提问需要具体经历依据，包括“面试官让我介绍项目”“考了手写快排”等要求，以及有面经条目、岗位／日期和对应问题的列表；不要求第一人称、轮次、编号或问号。

- 准备建议、未确认问过的补充题、候选人反问、作者向网友求助、招聘要求和教程单列，不计为实际面试题。问方不明时标“问方待确认”，不能擅自改成候选人反问。
- 保留原句的错字、重复字、英文拼写和语病，不润色、不补答案或生成新题，不把术语扩写成考题。连续追问可同题保留，不能拆成失去语境的碎片。
- 只摘录已读文字；截断、缺引用或未读图片中的题说明缺口，不补句意。独立编号的重复提问仍分别保留；正文与图片中同一题只计一项并列出处。

| 材料 | 每题定位方式 |
|---|---|
| 帖子 | 公开链接、原句，已有标题／轮次一并保留 |
| 图片 | 帖子链接、实际看清的转录原句及图内题号／段落；确认原图号才使用，否则写本地图片编号，不把下载顺序当原图序。可凭明确题号或轮次整理乱序图片，归属不清不猜接续，模糊文字标明 |
| B站字幕／简介 | 视频规范链接、分P与字幕 `from`／`to` 时间段、字幕原句；简介写明“视频简介”及原句。不把字幕序号当题号，不静默纠正自动字幕中的术语 |
| 本地文本 | 实际文件路径与核对过的行号；无稳定行号时用篇章标题和原句 |
| 直接贴文 | 来源标题或“用户提供材料 1”等标识，加原句，不虚构 URL 或文件 |

来源链接可在篇首定义，每题仍须保留定位与原句。图片只暂存供审读，不自动上传为附件。

## 交付与飞书

默认输出 Markdown，按来源、经历和轮次列出元数据及实际提问；建议、补充题和待确认项另列，不强制空栏目。指定文件就写文件，否则在对话交付。按实际已读范围报告完成与缺口。

用本地工具计数并复用同一份统计，区分来源数、面经数、摘录项与有经历依据的题目／要求；连续追问题组不冒称独立题数。交付或写表前，逐题对照正文／图片核对原句、问方、归属和元数据；写后回读不能替代原文审读。

用户要求飞书时按[飞书说明](feishu-base.md)完成目标核对、采集前排重、两表写入与回读，不重复采集已有材料或额外交付未要求的 Markdown 文件。字段、默认目标、补齐／迁移及失败恢复只在该说明维护；完成入库和核验后按[图片清理规则](feishu-base.md#入库后的图片清理)删除本批采集副本。

## 收尾：岗位题库选项

每次完成原题整理或入库后提示一次“继续积累／生成或更新岗位题库／生成学习包与本地刷题页”，让用户选择岗位或专题及范围。已明确选择、授权同步更新或本轮只要原题时直接按选择执行，不重复问；未授权不创建或更新题库。

展示已核实范围的各岗位面经数和题目数，不设置数量门槛、不为提示额外遍历整库，也不把本批数量当累计数。选择后按[岗位题库](role-question-bank.md)执行，每个岗位一张派生表。

选择学习或刷题时按[学习包](study-pack.md)直接复用已有材料，不要求先写飞书或重新采集。
