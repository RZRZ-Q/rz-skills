# 研究方向与团队脉络

## 按请求确定研究入口

以关注团队的近期研究指导选方向时，沿用用户目标和相关 watchlist 的团队、主题与时间范围，从这些团队的实际工作提炼研究问题。先比较有证据支持的方向，再筛选适合个人的切口。只恢复本轮相关范围，不默认扫描整份公司清单。用户直接指定技术问题、业务场景或单篇论文时，可以从该问题进入，不要求先做团队盘点。

团队范围决定哪些工作支撑本轮方向判断；外部论文、基准和代码可用于补背景、核对最近邻或检验候选，保留各自作用。外部材料改变了对研究差异的判断时，回到原方向重新评估切口；没有足够范围内证据时报告缺口，不将自由主题探索的结果当作团队研究脉络。

## 从论文平台补齐团队研究

公司官网／博客之外，同时检查 arXiv、Hugging Face Papers、作者公开页与官方项目仓库。只挂在论文平台的工作同样纳入；官网没有发布不能视为团队没有研究。使用团队中英文别名、作者、主题组合检索，例如 `ByteDance Seed agent evaluation`、`Tencent Hunyuan benchmark`，再读取原论文。Hugging Face 的 Daily Papers 只是部分被提交的论文，不是完整论文库。

论文模板中明确出现 Seed、Hunyuan 等团队署名、Logo、页眉／页脚品牌标识，也算团队关联证据。按实际所见记录，不强制要求官网博客背书：

| 实际依据 | 收录方式 |
|---|---|
| 论文作者单位／团队署名／联系邮箱明确归属 | 纳入团队研究，记录发表时归属与合作机构 |
| 首页或模板明确团队名称、Logo 或品牌标识 | 纳入团队关联研究，标明 `paper_branding`；未明确作者单位时不擅自补成全员隶属或团队独立完成 |
| 官方组织的 HF 关联、模型／数据卡或项目仓库指向论文 | 保存互链并核论文，记录组织关联依据；与论文自身署名分别保留 |
| 只有相似版式、搜索关键词、普通用户提交，或正文使用／对比某模型 | 作为候选或相关方法材料；不凭这些确认团队产出 |

`affiliation_evidence` 保存组织／团队、`basis`（如 `author_affiliation/paper_branding/official_crosslink`）、证据 URL、PDF 页码或 HTML 位置、简短原文／图形描述、核验时间；正文中的合作作者归属与品牌关联可以同时保留。品牌标识在图片中时查看首页／相关页，不能只依赖文本抽取。未确认主导方就保留合作关系，不作强行排名。

同一 arXiv ID 在 arXiv、HF Papers、博客与代码之间只计一个独立工作。记录实际读取版本、首次公开日期、版本日期与本轮获取日期；新版本保留历史。HF `.md` 若退化成摘要页，只能标摘要可读；HF AI 摘要与热度不能替代论文方法／实验正文。没有 HF 页面不等于没有论文，回退 arXiv HTML/PDF；平台关联只负责发现和归属，方法判断仍按实际阅读章节。

### 固定发现清单与扩充

| 目标 | 检索别名 | 交叉核对 |
|---|---|---|
| 字节 Seed | ByteDance Seed、Seed、字节 Seed | 论文署名／Logo、ByteDance-Seed 组织互链；单独 Seed 关键词须消歧 |
| 腾讯混元 | Tencent Hunyuan、HunYuan、混元 | 论文作者单位／页眉、Tencent-Hunyuan 互链；保留高校合作关系 |
| 阿里千问 | Qwen、Qwen Team、Alibaba、通义千问 | 作者单位和明确 Qwen 标识；使用 Qwen 模型本身不构成团队归属 |
| OpenAI | OpenAI、作者公开姓名 | 发表时单位／机构标识；作者当前任职不覆盖历史归属 |
| Anthropic | Anthropic、作者公开姓名 | 论文署名、官方公开互链；模型使用论文另记相关方法 |

每轮按目标范围选择已启用团队，将别名与用户目标主题及其检索术语组合，查 [arXiv](https://arxiv.org/search/) 与 [HF Papers](https://huggingface.co/papers)。HF 的公开 `/api/papers/{arxiv_id}` 元数据用于发现候选；`/papers/{arxiv_id}.md` 或 arXiv 正文由[采集主流程](collection.md#采集主流程)保存阅读队列后获取，再核对实际版本。接口不可用时记录失败，并按同一候选切换公开读取路径。上述查询式是发现起点，不声称平台搜索覆盖所有论文。

新发现团队先保存别名、候选论文 ID 和归属证据；核实团队关系后，在用户已授权公司范围内更新关注清单。仅核验署名或品牌标识用于来源归属，不自动生成论文分析记录；任务包含论文采集或分析时，按实际阅读范围保存材料。连续追踪保存上轮成功检查时间与已见 arXiv ID，检索时间留重叠区间以容纳迟收录；复查已跟踪论文版本，只有实际重新读取才更新观察时间。新增平台只增加发现路径，不增加独立工作数。用户未要求定时任务时保持手动执行。

## 先理解独立工作

读取论文的研究问题、方法、关键实验和相关限制，记录具体章节及实际阅读范围。官方博客可解释背景与实现取舍，核心实验结论仍回到论文／技术报告。来源只有摘要时可列待读线索，不写已经核验方法或性能。

每项工作回答：解决什么问题；相对其基线改变了什么；数据、模型、环境与评测条件是什么；结果支持什么结论；哪些资源、代码或评测资产可用。优先讲有证据的贡献与可学习价值，必要边界就近交代。

选题依赖某项数据或实现时，核对正文、附录、作者项目页与仓库互链，包括正文中的纯文本地址；检查关键文件或必要样本，不以目录／README代替资产可用性。分别记录已发布、部分发布、访问失败和本轮未发现，避免把访问或链接提取失败写成“作者未公开”。实际下载、实现阅读与运行验证各有各的范围。

## 再连成团队脉络

使用发表时的团队／作者信息、稳定论文 ID 和官方关联，把一段时间内的工作串起来。区分同一论文的新版本、同一工作的博客与真正的新工作。

比较连续作品中的问题、方法、数据和评价变化。能看到前后作品时给出有日期的关系，例如“从静态交互样本扩展到在线任务”；只有单项工作时交付该项研究重点，不外推团队长期战略。公开论文反映已公开工作，与团队内部计划及当前岗位需求分开。

作者同名、跨机构合作或团队不明确时保留归属证据；不能把公司所有 Agent 论文归给同一个 Lab。博客发布较晚不意味着研究发生较晚，关注论文首次公开与版本时间。

需要据此推荐方向时，整理“研究问题／方向—来源团队与具体工作—本轮观察到的进展或差异—可迁移资产与未解决问题”，让优先级能回到已读证据。多个团队确实研究同类问题时再讨论共同关注；单篇工作只能支持该工作的观察，不凭论文数量排序团队热度。保留本轮未覆盖、仅摘要可读或归属待核的范围，不要求每个团队都产出一个选题。

## 转成学生能做的事

对团队研究导向的请求，先给方向比较和个人适配理由，再展开优先方向的具体任务；每个候选说明它承接了哪项研究观察。用已有基础和资源决定推进深度，可以从复现、测量或局部改造开始，不为凑原创题目而跳过方向判断。已指定具体问题的请求则直接细化该问题。

按目标选择一种产物即可：

- **理解与复现**：读哪些关键章节，运行哪个官方入口，在什么数据和资源条件下复现哪部分。
- **工程改造**：将方法应用到已有场景，明确自己要改变的模块和验证任务。
- **研究候选问题**：从原工作的具体观察或未覆盖条件提出可检验问题，写出假设、最小对照、指标、支持／推翻假设的现象及资源要求。

这三类不能混称原创研究。日常追踪可以只给复现或待检验线索；为原创研究或投稿潜力排序时，再执行下面的候选核查。检索深度随主张而定，不把普通论文介绍扩成完整选题流程。

### 候选问题与近邻核查

先用一句话定义研究问题，写清研究对象、可见输入、拟改变的因素、实验条件和结果指标，再据此找近邻，而不是只搜团队名或原论文标题。

- 用问题、机制和拟主张的现象分别检索，包含常见别称与相邻任务中的同等问题；团队范围限制方向依据，不限制最近邻的机构来源。
- 从最接近原文的相关工作、直接对照和项目互链追查，并检查后续工作与当前可得版本。旧工作即使早于用户的近期窗口，仍可能是必需对照；首发时间和所读修订时间分别记录。搜索引擎、论文平台或版本的重复命中不算独立覆盖。
- 对可能改变贡献判断的近邻，读取对应方法、实验、协议或附录，记录原文位置。不要凭摘要未提到就判定该文没做，也不要用下载全文代替实际阅读。能影响推荐的正文不可读时，保留具体未决比较，降低该主张的确定性。
- 按候选主张整理“已有工作及证据位置—相同与不同条件—已覆盖的主张—仍待检验的差异—直接对照与资产状态”。既查方法近邻，也查已经测过同一现象的评测／分析工作。检索达到足以判断本轮差异和直接对照时收束，报告剩余缺口，不设论文数量配额或无限扩查。

发现重叠时，更新候选问题、贡献描述、对照和优先级；仅在改题带来新的检索术语或比较对象时补查相关部分。换数据集、任务名称或预算规模本身不证明新颖性；若主要价值是外部验证，应说明它检验了原结论的哪项适用条件。没有可区分差异时可推荐复现，不为保留“科研候选”而硬造新算法。

### 从贡献主张到实验

每个保留候选说明拟贡献属于新方法、新测量发现还是既有结论的外部验证，并把主张对应到假设、支持／推翻现象和所需证据。研究问题尚未验证、直接资源尚未核验和实现尚未运行是不同状态，分别交代，不合成一个笼统“可复现”。

有方法收益主张时，纳入最近邻可用的直接方法或设置，再设计区分新增因素的消融；测量题则对照已有测量协议及其结论。比较各方法可用的信息、标签、训练／校准范围与评价分母。直接实现不可取得时说明重建范围；模块尚未接通时把输入契约、可用元数据和实际触发列为先导条件，不把无效开关当作机制消融。

自然数据／真实流程与人工构造、oracle 输入、离线代理终点分别报告。受控干预要说明到底改变了哪些信息或因素：声称证据齐备时，依据必须已足以确定目标；若干预首次补入决定答案的新事实，解释为信息补全，不能归因于原证据的使用能力。相同长度、格式或预算只控制相应因素，不能自动证明其他因素不变。不同方法各自筛出的成功或完整子集只支持各自描述；主方法比较需保持可解释的共同评价对象。

把机制对齐到用户能完成的最小实验。按[准备计划](../_shared/references/advice.md#准备计划与反馈)核算唯一产物、人工覆盖和实际调用；区分独立来源组与其改写、条件、重复输出，按任务家族隔离开发和测试。默认规模保留支撑主张的直接对照与诊断，扩大数据、模型或重复次数作为条件扩展。

先导用于检查任务是否成立、标签能否判断、有没有可测现象以及实际标注时间和调用成本；用它修正默认规模。小样本中先看分母和单例对比例的影响，不把几个百分点的波动直接当成方法成立或题目去留依据。效果目标与运行可行性判据分别记录；先导看过的任务保留开发身份，冻结方案后的测试承担正式主张。没有收益时，可据真实发现收束成复现、测量或误差分析，不能把计划阈值写成实验结果。

用户问投稿价值时，说明最有希望形成的具体贡献和需要什么证据，而不是估计接收概率；近期关注度、招聘准备价值与研究差异分别判断。只做推荐时可以规划必要的后续真实实验，并将它与本轮实际执行范围分开。

需要岗位映射且有 JD 证据时，把所训练的能力对应到要求原句：评测设计、环境搭建、长程推理、奖励验证或后训练等。映射属于准备价值判断，不能声称对应团队正在招聘该论文方向。按[衔接说明](../_shared/references/handoffs.md)将来源依据、近邻差异、实验条件与预算假设交给 `ai-career`，由它结合个人优势决定优先级。
