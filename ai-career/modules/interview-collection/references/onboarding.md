# 首次引导与执行配置

## 1. 检查并准备环境

按本轮入口检查，报告“可用／缺少／待用户完成”；新目录不代表依赖齐全。仅整理文字只需材料可读，涉及图片再检查宿主读图能力。平台或输出未定时先盘点本机能力，问清决定依赖的入口，不安装未选路线的工具。

可先用随包[环境工具](environment.md)按本轮功能检查版本和缺失项；安装只补所选模块，不升级全局环境。工具可执行不代表浏览器已登录或飞书目标有权限。学习包／本地页面按[学习流程](study-pack.md)选择文件依赖，无需检查未使用的平台。

| 本轮能力 | 检查与缺失时的指导 |
|---|---|
| 牛客脚本、小红书图片下载 | `python3 --version`，需要 Python 3.9+；缺失时按当前系统的 [Python 官方说明](https://www.python.org/downloads/)指导安装 |
| 小红书／知乎／B站浏览器 | 先检查 `opencli --version`；选定浏览器路线后再核对本机帮助、`doctor`、`profile list` 和后台参数。工具缺失时按[环境准备](environment.md)检查 Node.js，并优先局部安装到项目 runtime；按 [OpenCLI 官方说明](https://github.com/jackwener/OpenCLI#quick-start)配置 Browser Bridge，桌面安装器按其说明处理 |
| 浏览器身份与登录 | 沿用用户所选 profile；未指定或多个候选时询问。指导在该 Chrome profile 启用 Bridge 并手动登录，命令用 `--profile`，不改全局身份；`xhs-collector` 不是通用必备名称 |
| 飞书 | 检查 `lark-cli --version`、`--help` 和 `lark-base`、`lark-shared`。缺失时按 [官方安装说明](https://github.com/larksuite/cli#installation--quick-start)使用 `npx @larksuite/cli@latest install`，该交互流程包含工具、Skills 与配置；只补缺失项。认证按本机或[官方 lark-shared](https://github.com/larksuite/cli/blob/main/skills/lark-shared/SKILL.md)，身份和目标核对按[飞书说明](feishu-base.md) |

首次选择需登录的平台账号时，简短提醒一次：建议使用采集专用的小号和独立 Chrome profile，与日常账号分开。该建议可选，用户可继续使用已授权账号；遇访问限制仍按平台规则停止，不自动换号继续。

给出适合本机的具体步骤；已授权代装的部分直接完成，需用户启用浏览器、登录或授权时说明操作位置并等待，完成后复检。复用满足命令需求的版本，不自动升级或覆盖配置；不支持所需参数时报告差异。不要索要或输出密钥、Cookie、令牌。

环境阶段不试写或批量搜索。Bridge 连通不证明平台登录；方案确认后，用首个预算内的真实读取核验可读性，按平台规则处理登录要求、验证码及访问限制。飞书认证成功不替代目标权限与关联核对。

## 2. 集中询问任务变量

环境就绪后集中补齐缺失条件，提供推荐默认项；给定链接不问搜索条件，已有材料只问整理和输出选择。

- **对象**：公司／公司范围、岗位或方向、时间与招聘类型；未限制的条件不自行添加。
- **平台**：默认推荐牛客＋小红书，知乎、B站须用户选择；分清“小红书公司”和“小红书平台”。选择B站时说明当前读取简介和可用字幕，无字幕不默认下载或转写整段音视频。
- **数量与预算**：默认最多 5 个来源、合计 3 批搜索和 5 篇详情，筛选后可能不足。更大任务先明确总上限与分批计划；来源数和拆出的面经数分开报告。
- **输出与目标**：Markdown 或飞书；飞书选择新建或追加。默认配置只作候选，独立测试不读写旧目标，新建不自动设为默认。
- **并行度**：说明下表中本轮相关项，再问“保留默认／全部串行／按平台指定”。数值表示独立请求或已开页面数，不是 Agent 数或目标篇数。

### 常用意图理解提示

理解请求时可用下面的提示；向用户只给简短结论和必要问题，不逐项重复解释：

> 区分来源平台与面试公司、实际岗位与题干技术、毕业届次与招聘季、累计目标与本批新增量。先沿用已确认条件，再把本次变化合入方案；区分“只要”的硬性条件与“优先”的偏好，搜索词可替换而筛选范围不变。会改变采集范围的歧义给出候选解释，合入本次提问或方案确认。

| 用户说法 | 理解与必要澄清 |
|---|---|
| “27 届校招面经” | 届次指毕业人群，不是原文必含的关键词。通常涉及 2026 秋招、2027 春招；未说明招聘季且上下文不明时问“秋招、春招还是都要？”；已说 2026 秋招则直接沿用，不把实习自动并入。其他届次按对应年份理解，证据按[采集判断](find-interviews.md#逐条判断)核对 |
| “算法或 Agent 岗面经” | 两者满足其一，依据实际岗位名称／明确同义称呼，不依据题干谈到算法或 Agent；用户说“名称必须含”时保留该字面限制。用户的排除条件同时有效，不能擅加产品或开发岗限制 |
| “小红书上的腾讯面经”／“小红书算法岗面经” | 前者指定来源平台和腾讯公司；后者通常指定小红书公司，来源按已确认平台。上下文仍无法区分时才问 |
| “补到 100 篇”／“再加 100 篇” | 前者是同范围累计目标，后者是新增目标。先核对已有符合范围的数量及来源数／面经数口径，只计同范围结果，不把面经拆篇数当作来源数；数量目标不自动扩大访问预算 |
| “继续” | 沿用最近已确认的任务及剩余预算，不重置额度。预算已尽时，只有回复明确的续批方案才采用其新额度，否则补问该批上限；范围、平台和目标不重复问 |

## 3. 说明默认并行度，再让用户选择

| 操作 | 默认最大并行数 | 验证范围 |
|---|---:|---|
| 牛客脚本独立请求 | 3 | 规则默认值，现有已核对记录为串行，尚未验证三路成功 |
| 小红书已打开页面提取正文／日期／图片地址 | 3 | 已有三路成功记录，页面先逐个打开 |
| 知乎已加载页面提取 DOM | 2 | 仅双路 DOM 小样本成功观测，不代表详情 adapter 或整轮验收通过 |
| B站搜索、视频详情、字幕 | 1 | 原生命令会发起导航或网络读取，先串行；尚无并行验收 |
| 浏览器导航、搜索页交互、滚动、翻图、截图、图片下载；飞书写入 | 1 | 保持串行，不随读取并行数调高 |

用户可调低；调高时说明未验证范围，在原总预算内确认具体操作、数值及首批上限后小批试跑，不扩访问量或改变串行环节。“加快”不等于指定更高数值。独立来源与输出不混用；失败后停止新增调用、收齐在途结果，按平台规则处理。一次成功不代表长期安全频率。

## 4. 汇总并确认执行

将范围、平台、数量与访问上限、并行度、输出和目标汇总为一段，首次引导确认后开始；配置、登录及必要答案未完成时不提前采集。已有完整方案和执行授权直接沿用，续批保留该批目标与并行选择。

结束后按[整理收尾](organize-interviews.md#收尾岗位题库选项)提示题库选择，无需在首次引导强迫用户决定尚无材料的题库范围。
