# 从真实结果续接个人进展

用于保存个人项目／成长计划，或在用户提供项目产物、学习结果、面试反馈后继续下一步。能力诊断见[分析与建议](advice.md)，成果与主张对应见[项目规划](projects.md)。普通岗位搜索、论文查询或方向概览不需要建立个人进展记录。

## 找回当前目标与证据

先按[共用存储](storage.md)解析同一个数据根目录，读取 `data/career/state.json` 中相关目标、项目、行动及其计划／最近复盘引用，再读取本轮所需的具体证据。不依赖上一轮对话或 shell 目录，也不把雷达的 `career_handoff` 当作个人进度索引。

没有索引时，从用户明确指定、当前交接直接关联或已经确认属于该目标的旧计划开始，保留原文件与引用位置；不能按文件修改时间任取一份报告当成当前计划。历史中的示例画像、条件化建议和测试人物不是用户事实。无法确定归属时仅补问会影响续接的缺口，仍可分析已明确提供的产物。

用户本轮明确目标和约束优先于旧计划；记录变化与受影响的行动。多个目标都在进行时保留各自身份，不把新方向覆盖到另一个项目。现有个人画像文件仅引用已有路径，不要求迁移或新建统一画像。

## 用结果更新行动

1. 读取原验收条件与新增代码、运行结果、演示、解释或反馈，标出实际检查的文件／版本／任务范围。沿用已有 `project_id`、`action_id` 和 `claim_id`，不因换会话或改标题重新建项目。
2. 将执行状态与核验状态分开。例如用户自述已完成，可以记为 `execution=completed`、`verification=pending`；缺少结果时不替用户宣布未做，也不据自述宣布验收通过。`verified` 仅表示该行动的约定条件已由记录中的证据覆盖，不等于全面掌握该技术。
3. 只调整受新证据影响的能力、成果主张、未完成动作和剩余工作量。版本改变后，旧版结论仍是历史事实，新版受影响部分等待对应证据；未改动且仍适用的结论无需全部重验。结果被纠正时保留原结论及纠正依据。
4. 说明实际完成了什么、现在能支持什么、尚卡在哪里，以及下一步的产物和验收理由。按剩余任务重估时间与预算；日历时间过去、勾选完成、生成报告或读完资料都不自动等于能力提高。

个人进展可以引用原有岗位 `job_key`、材料 `material_id/work_id`、项目路径和版本，不复制正文或创建第二份采集库。外部面经学习进度只有在实际读到记录或用户提供导出时才纳入，浏览器中的练习状态不会自动同步到这里。

## 重复反馈与增量

保存前，按同一项目／行动和已有反馈比较本轮新增信息：

- 同一产物用原始路径或仓库／提交定位，加实际内容摘要或哈希确认版本；仅改文件名、复制路径或再次发送同一反馈不算新成果。
- 反馈优先沿用来源记录 ID；没有 ID 时保留反馈正文／可定位引用和关联行动。相同含义、同一证据范围的重复自述不推进完成状态，不新增项目或完成次数。不要仅凭接收时间生成一个“新结果”。
- 同一产物的新增核验可以更新核验状态；新版本、纠正的结果或新的解释证据也可能改变结论。记录具体增量及被替代的判断，不将它们当重复而丢弃。

对照最近复盘中的已处理反馈与证据引用，必要时沿其上一轮引用查对应旧记录；不必扫描整库。没有新增事实、核验或决策变化时，直接返回已有结论和下一步，不改索引、不重复创建复盘。存在新增信息时仅写本轮变化，并保留已有项目／行动身份。

## 最小保存约定

继续使用存储助手返回的 `root`，按需在其下保存：

```text
data/career/state.json          当前个人目标、项目与行动的轻量索引
reports/career/<run-id>.md      每轮计划／复盘及证据判断
```

这些路径由 `root` 拼接，不是 `storage.py` 已返回的新字段，也不参与其 `initialized` 判断。首次需要保存个人计划时才创建；旧 JD、watchlist、雷达基线、个人文件及历史报告原位保留。

`state.json` 使用以下小型约定；只保留恢复当前工作所需信息，不在其中复制完整能力表、主张表或采集正文：

| 字段 | 内容 |
|---|---|
| `schema_version` | `1` |
| `active_goal_id` | 本轮正在处理的目标 ID |
| `goals` | 目标列表：稳定 `goal_id`、`summary`、必要 `constraints`，已有画像时可加 `profile_ref` |
| `projects` | 项目列表：稳定 `project_id`、所属 `goal_id`、`title`、`plan_ref`、`latest_review_ref` |
| `actions` | 行动列表：稳定 `action_id`、所属 `goal_id`／按需 `project_id`、`summary`、`execution`、`verification`、`evidence_refs`、`next_step` |
| `latest_review_ref` | 最近一轮已成功保存的报告引用 |

执行状态用 `planned / in_progress / completed / paused / cancelled`；核验状态用 `pending / verified / needs_work / not_applicable`。无须产物验收的选择类行动才可用 `not_applicable`；完成与核验互不替代。ID 首次保存时分配，之后复用。路径相对于数据根目录；库外产物保留可访问的原始绝对路径或仓库引用，并说明实际核验的版本。

每轮报告按需包含：

- 本轮目标、与上一轮的关系及上一轮报告引用；首次采用旧计划时标明来源和采用范围。
- 已处理的反馈／证据引用与版本、关联行动、实际阅读或执行范围；重复与新增信息的判断依据。
- 当前相关能力表、成果主张表（含稳定 `claim_id`）与变化理由，区分自述、实测和待核。旧结果被纠正时引用原记录，不覆写它。
- 可直接续接的当前摘要：相关项目／行动 ID、执行与核验状态、未完成项、下一步产物／验收及剩余预算。详细代码、原始日志继续引用原位置。

先保存新的报告，确认引用与内容可读，再以同目录临时文件替换索引并回读 JSON 和所指报告。报告写入失败时不推进索引；索引更新失败时说明尚未续接成功，保留已经写好的报告供恢复，不重做已完成工作。不要覆盖已有同名报告。任务只要求分析而不保存时，交付判断及建议即可。
